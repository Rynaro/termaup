# SPECTRA Conventions — termaup (clickup-rs)

> Generated by SPECTRA v4.2.0 on 2026-04-09
> Adapted from codebase analysis of the clickup-rs Cargo workspace.

---

## Quick Reference

1. **Three-crate workspace**: `clickup-api` (lib) → `clickup-cli` (bin) + `clickup-tui` (bin). The two binaries never depend on each other.
2. **Endpoint methods live on `ClickUpClient`**: Business logic is `impl ClickUpClient` blocks in `crates/clickup-api/src/endpoints/<resource>.rs`, named `get_*`, `create_*`, `update_*`, `delete_*`.
3. **Models are defensive serde structs**: Every model derives `Debug, Clone, Serialize, Deserialize` with only `id` + `name` required; everything else is `Option<T>` or `#[serde(default)]`.
4. **Errors split by crate role**: `thiserror` + `ClickUpError` in `clickup-api`; `anyhow::Result` + `.context()` in binaries.
5. **All async, all tokio**: Every I/O function is `async`, HTTP requests have 30s timeouts, TUI data fetches use `tokio::spawn` + `mpsc` channels.

## 4. Example Story

### Story: Add a health-check endpoint returning service status and version

**Title:** Implement `/health` diagnostic endpoint on `ClickUpClient`

**As a** developer integrating clickup-rs,
**I want** a `health_check()` method that validates connectivity and returns version info,
**so that** CLI and TUI can verify configuration before making real API calls.

#### Acceptance Criteria

1. `ClickUpClient::health_check()` calls `GET /user` and returns `HealthStatus { ok: bool, user: Option<String>, version: String, latency_ms: u64 }`.
2. The `HealthStatus` model lives in `crates/clickup-api/src/models/health.rs`.
3. The CLI exposes `clickup health` printing a table with status, user, version, latency.
4. On auth failure, `ok` is `false` and `user` is `None` — no panic or error propagation.

#### Implementation Steps

| # | Action | File | Details |
|---|--------|------|---------|
| 1 | Create model | `crates/clickup-api/src/models/health.rs` | `HealthStatus { ok, user, version, latency_ms }` — derive `Debug, Clone, Serialize, Deserialize` |
| 2 | Extend models/mod.rs | `crates/clickup-api/src/models/mod.rs` | Add `pub mod health;` + `pub use health::*;` |
| 3 | Create endpoint | `crates/clickup-api/src/endpoints/health.rs` | `impl ClickUpClient { pub async fn health_check(&self) -> Result<HealthStatus> }` |
| 4 | Extend endpoints/mod.rs | `crates/clickup-api/src/endpoints/mod.rs` | Add `pub mod health;` |
| 5 | Create CLI command | `crates/clickup-cli/src/commands/health.rs` | `#[derive(Subcommand)] enum HealthCommands { Check }` |
| 6 | Extend CLI main | `crates/clickup-cli/src/main.rs` | Add `Health` variant to `Commands` enum |
| 7 | Test endpoint | `crates/clickup-api/src/endpoints/health.rs` | `#[cfg(test)] mod tests` with `wiremock` — test success + auth failure |

  - [ ] P0: `cargo build --workspace` succeeds

## 5. Project-Specific Rules

### Architectural Boundaries

- **`clickup-api`** must NEVER depend on `clap`, `ratatui`, `crossterm`, `comfy-table`, `dialoguer`, or any CLI/TUI crate.
- **`clickup-cli`** and **`clickup-tui`** must NEVER depend on each other.
- All cross-crate dependencies flow inward: binaries → `clickup-api`.
- Use **workspace dependencies** (defined in root `Cargo.toml`, referenced as `dep.workspace = true`).

### Naming Conventions

- **Files:** `snake_case.rs` — one file per entity/resource/screen.
- **Structs:** `CamelCase` — `Task`, `ClickUpClient`, `TaskCommands`.
- **Functions:** `snake_case` — `get_tasks`, `spawn_load_spaces`, `render`.
- **Constants:** `SCREAMING_SNAKE_CASE` — `DEFAULT_BASE_URL`, `TIMEOUT_SECS`.
- **Endpoint methods:** `get_<resource>`, `get_<resource>s`, `create_<resource>`, `update_<resource>`, `delete_<resource>`.
- **TUI spawn functions:** `spawn_load_<resource>` or `spawn_<action>_<resource>`.
- **CLI command enums:** `<Resource>Commands` with verb variants (`List`, `Get`, `View`).

### Defensive Deserialization (ClickUp API)

- Only `id` and `name` are required fields on model structs.
- `Vec` fields: `#[serde(default, deserialize_with = "deserialize_null_as_default")]`.
- ID fields: use `deserialize_string_or_number` (API mixes `"6"` and `6`).
- Sub-objects: `Option<T>` + `#[serde(default)]`.
- Boolean fields: consider `deserialize_bool_or_int` (API sends `0`/`1`).
- Every new model must be tested with: full, minimal (id+name only), null-heavy, and type-mixed JSON payloads.

### Error Handling

- **Library (`clickup-api`)**: `thiserror` — `ClickUpError` enum with variants: `AuthError`, `ApiError`, `RateLimited`, `NetworkError`, `DeserializationError`, `ConfigError`, `NotFound`.
- **Binaries (`clickup-cli`, `clickup-tui`)**: `anyhow::Result` with `.context("descriptive message")`.
- NEVER `.unwrap()` outside test code.
- NEVER `panic!()` in library code.

### Testing Requirements

- Use `#[tokio::test]` for all async tests.
- Use `wiremock::MockServer` for HTTP mocking — never hit real ClickUp API.
- JSON fixture files in `tests/fixtures/` for integration tests.
- Test naming: `test_<what>_<condition>_<expected>`.
- Use `insta` for snapshot tests on CLI formatted output.
- TUI rendering tests use `ratatui::TestBackend`.

### CLI Output

- Success: green `✓` prefix via `output::success()`.
- Error: red `✗` prefix via `output::error()` to stderr.
- Info: blue `ℹ` prefix via `output::info()`.
- Tables: `comfy-table` with `output::print_table()`.
- JSON: `output::print_json()` pretty-printed 2-space indent.
- Colors: `owo-colors` — never raw ANSI escapes.

### TUI Architecture

- `App` struct holds ALL state — screens are stateless render functions.
- `Screen` enum drives dispatch: `Loading → WorkspaceSelect → SpaceList → SpaceContent → TaskList → TaskDetail`.
- Data fetching: `spawn_load_*` in `data.rs` → `tokio::spawn` → `mpsc::UnboundedSender<AppEvent>`.
- Never block the main render thread.

### CI Quality Gates

Every PR must pass (in order):
1. `cargo fmt --all -- --check`
2. `cargo clippy --workspace -- -D warnings`
3. `cargo test --workspace`
4. `cargo build --workspace --release`

### Git Conventions

- Conventional commits: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`.
- One logical change per commit.
