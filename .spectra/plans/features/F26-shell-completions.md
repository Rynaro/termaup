# F26 — Shell Completions

> **SPECTRA v4.2.0** — Feature plan
> **Date:** 2026-04-11
> **Phase:** 6 — Distribution & Infrastructure
> **Complexity:** 3/12 | **Confidence:** 95%

## Problem Statement

The `clickup` CLI has a growing number of commands and subcommands but offers no shell completion support. Users must type full command names, subcommand names, and flag names from memory or consult `--help` repeatedly. Shell completions for bash, zsh, fish, and PowerShell would significantly improve discoverability and typing speed.

## Approach

Use clap's built-in `clap_complete` crate to generate shell completion scripts at runtime. Add a top-level `clickup completions <SHELL>` command that outputs the completion script to stdout. Users pipe the output to their shell's completion directory or source it in their shell config.

This approach is simpler and more maintainable than build-time generation: the completion script always matches the installed binary's exact command structure, and no build system changes are needed.

### Rejected Alternatives

1. **Build-time generation via `build.rs`** — Generate completion files during `cargo build` and embed them in the release archive. More complex to implement, requires maintaining a `build.rs` script, and the generated files can become stale if a different binary version is installed. Rejected for complexity.

2. **Manual completion scripts** — Hand-written completion scripts for each shell. Extremely fragile — every new command or flag requires manual updates to 4 separate scripts. Rejected for maintenance burden.

3. **Third-party completion crate** — Crates like `clap_complete_nushell` for additional shells. Premature — bash, zsh, fish, and PowerShell cover >99% of users. Rejected as deferred.

## Scope

| In Scope | Out of Scope | Deferred |
|----------|--------------|----------|
| `clickup completions bash\|zsh\|fish\|powershell` command | Nushell completions | Auto-install completions in Homebrew formula |
| Runtime generation via `clap_complete` | Build-time generation | Completions for TUI binary (`termaup`) |
| Documentation in README/help output | Dynamic completions (e.g., completing task IDs from API) | |

## Stories

### S-1: Shell Completion Generation Command

**As a** CLI user, **I want** `clickup completions bash` to output a bash completion script, **so that** I can enable tab completion for all clickup commands and flags.

**Timebox:** ≤1d | **Risk:** Low | **Depends on:** —

#### Action Plan

| # | Action | File | Details |
|---|--------|------|---------|
| 1 | Add `clap_complete` dependency | `crates/clickup-cli/Cargo.toml` | `clap_complete = "4"` (or use workspace dep if defined) |
| 2 | Add `Shell` enum | `crates/clickup-cli/src/commands/completions.rs` | Create new command module with `Shell` arg from `clap_complete::Shell` |
| 3 | Create `CompletionsCommand` | `crates/clickup-cli/src/commands/completions.rs` | `#[derive(Parser)] struct CompletionsCommand { shell: clap_complete::Shell }` |
| 4 | Implement generation | `crates/clickup-cli/src/commands/completions.rs` | `pub fn execute(shell: Shell) { clap_complete::generate(shell, &mut Cli::command(), "clickup", &mut std::io::stdout()) }` |
| 5 | Register in commands/mod.rs | `crates/clickup-cli/src/commands/mod.rs` | Add `pub mod completions;` |
| 6 | Register in main.rs | `crates/clickup-cli/src/main.rs` | Add `Completions { shell: clap_complete::Shell }` variant to `Commands` enum, route to handler |
| 7 | Test script generation | `crates/clickup-cli/src/commands/completions.rs` | Unit test: generate for each shell, verify output is non-empty and contains `clickup` |

#### Acceptance Criteria

- **GIVEN** `clickup completions bash` is run, **WHEN** output is captured, **THEN** it contains valid bash completion code including the string `clickup`.
- **GIVEN** `clickup completions zsh` is run, **WHEN** output is captured, **THEN** it contains valid zsh completion code including `#compdef clickup`.
- **GIVEN** `clickup completions fish` is run, **WHEN** output is captured, **THEN** it contains valid fish completion code.
- **GIVEN** `clickup completions powershell` is run, **WHEN** output is captured, **THEN** it contains valid PowerShell completion code.
- **GIVEN** bash completion is sourced, **WHEN** the user types `clickup ta<TAB>`, **THEN** it completes to `clickup task`.
- **GIVEN** zsh completion is sourced, **WHEN** the user types `clickup task <TAB>`, **THEN** subcommands `list`, `get`, `view` are shown.

The completions command does NOT need a `ClickUpClient` — it's pure CLI introspection. Make sure the `completions` command does NOT require authentication (no `client_factory` call).

### S-2: Completion Installation Documentation

**As a** CLI user, **I want** clear instructions on how to install shell completions, **so that** I can set up tab completion for my specific shell.

**Timebox:** ≤0.5d | **Risk:** Low | **Depends on:** S-1

#### Action Plan

| # | Action | File | Details |
|---|--------|------|---------|
| 1 | Add completions section to README | `README.md` | Section "Shell Completions" with install instructions for each shell |
| 2 | Add help text to command | `crates/clickup-cli/src/commands/completions.rs` | `#[command(about = "Generate shell completion scripts", long_about = "...installation instructions...")]` |
| 3 | Document bash install | `README.md` | `clickup completions bash > ~/.local/share/bash-completion/completions/clickup` |
| 4 | Document zsh install | `README.md` | `clickup completions zsh > ~/.zfunc/_clickup && echo 'fpath=(~/.zfunc $fpath)' >> ~/.zshrc` |

| 6 | Document PowerShell install | `README.md` | `clickup completions powershell >> $PROFILE` |

- **GIVEN** the README, **WHEN** inspected, **THEN** installation paths are correct for each shell on standard setups.

#### Agent Hints

## Assumptions

1. **`clap_complete` 4.x is compatible with clap 4.x** already used in the project. Risk if wrong: none — these are maintained by the same team.
2. **Shell completion output from `clap_complete` is correct** and doesn't need manual tuning. Risk if wrong: low — `clap_complete` is mature and widely used.
3. **The `completions` subcommand does not conflict** with existing commands. Risk if wrong: rename to `completion` or `shell-completions`.
